# Performance baseline

Measured on 2026-08-07 with a Release build produced by SwiftPM.

## Environment

| Item | Value |
|---|---|
| Hardware | MacBookAir10,1; 8 logical processors; 16 GiB RAM |
| macOS | 15.7.7 (24G720) |
| Swift language mode | Swift 6 |
| Corpus | Deterministic UTF-8 mixed text generated by `TildeBenchmark` |

Run the same matrix with:

```sh
scripts/run-benchmarks.sh
```

Each size runs in a separate process so peak resident memory is not inherited
from a previous case. Open includes strict decoding, line-ending normalization,
`NSTextStorage` creation, and line-index construction. Typing includes a
one-character storage replacement, incremental line-index update, and document
change tracking. The benchmark is a regression baseline, not a substitute for
Instruments or interactive scrolling/IME tests.

## Markdown results

| Source | App / Textual | Quick Look / swift-markdown | Quick Look HTML | Peak RSS |
|---:|---:|---:|---:|---:|
| 1 MiB | 1.52 s | 0.53 s | 2.59 MiB | 129.2 MiB |
| 5 MiB | 8.28 s | 2.65 s | 12.94 MiB | 635.4 MiB |
| 10 MiB | 17.25 s | 5.40 s | 25.88 MiB | 1,284.8 MiB |

The App and Quick Look remain responsive through cancellation/process
isolation, but rendering beyond 5 MiB has disproportionate latency and memory
cost. The existing 5 MiB source budget is therefore a safety ceiling, not an
invitation to render every file at that size interactively.

## Decisions and v1 SLOs

- Enter Large File Mode at 50 MiB. Disable Markdown preview and word wrapping;
  retain editing, selection, Find, Go to Line, scrolling, and Save.
- Treat 100 MiB as the largest validated v1 open size. Refuse larger files with
  an explicit error rather than risk memory pressure in the whole-file editor.
- Keep the Markdown source ceiling at 5 MiB and do not offer `Preview Anyway`;
  the 10 MiB case used about 1.28 GiB and took over 17 seconds in the App path.
- Common documents up to 1 MiB: Open under 100 ms and Save under 100 ms on the
  baseline machine.
- 50 MiB corpus: Open under 2.5 seconds, Save under 3.5 seconds, typing P95 under
  1 ms, and peak RSS under 500 MiB on the baseline machine.
- 100 MiB corpus: Open under 5 seconds, Save under 7 seconds, typing P95 under
  1 ms, and peak RSS under 1 GiB on the baseline machine.

Release profiling must still capture Time Profiler, Allocations, and Hangs on a
signed candidate; those Instruments artifacts are machine-generated release
evidence and are not represented by this headless benchmark.
